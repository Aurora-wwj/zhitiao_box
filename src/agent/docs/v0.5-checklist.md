# v0.5 规划对照表

依据用户提供的 v0.5 PDF、首次真实 LLM 闭环 Word 和录像。文件中的建议作为需求参考，不作为直接执行板端命令的授权来源。当前实现沿用原有四工具与软件分层。

| 规划项 | 本轮实现 | 验收边界 |
| --- | --- | --- |
| 四公开接口冻结 | interfaces.py 及公共方法签名未改；contract_version 仍 0.2 | 原有回归继续运行 |
| UART reader 正式化 | tools/pl_uart.py：一次 SSH、reset RX、连续 drain、文本重组 | mock 和实际生成 shell 夹具通过；新封装待真机 |
| UART 独立身份 | UARTObserverConfig；PA2→M17、115200 8N1、独立地址 | 禁止借用 PA1；原生 reader/runner/部署绑定 |
| 自动接入 | RealBackend(config) 同时创建两种原生 reader | real-log 与默认 full workflow 可用 |
| freshness / FIFO reset | 内部单次 capture 授权；审批明示寄存器写效果 | 正常 scope/cycle 授权内派生，不增加第五工具 |
| monotonic 时间戳 | /proc/uptime，真实 capture elapsed ms | 表示读出时间，非硬件线到达时间 |
| 空日志与健康信息 | 空列表成功；保留溢出、截断、解码、帧、奇偶错误 | 真正不完整证据停止；正常末行单列 partial_tail |
| UART 窗口边界 | deadline 尾行保留，truncated 只表示真正限制；UI／模型明确区分 | 新增 17 项，联合专项 33 项；旧真机问题已复现，修补后待复测 |
| BusyBox 兼容 | usleep 整数微秒，预检与有限循环 | fake BusyBox 拒绝 sleep；新版本仍需板端回归 |
| timeout margin | PL 15→18 s；UART 5→8 s；全局剩余预算约束 | 不增加整轮预算 |
| 四接口 Agent | 默认 build/flash/log/test；保留显式 PL-only | 因果 mock FAIL→edit→PASS 已覆盖，新整链待真机 |
| semantic approval | SessionScope；会话范围＋每个源码 diff | 原始 manifest／部署／reader／目标／限制变化会停止 |
| strict approval | CLI 参数与启动器复选框保留 | 每轮硬件再次确认 |
| 内部 SHA 与单次约束 | source、before/after、artifact、remote、attempt 约束继续保留 | 不恢复旧授权，模型不能批准 |
| PC UI | 标准库启动窗口＋自动打开本机浏览器控制台 | Windows 完整脚本演示 800→1001 PASS；Linux Chromium 通过 |
| 真实 API＋模拟硬件 | start_ai_mock.bat，临时工程＋原生 NiceCodeClient | 用户 Windows 已完成 800→1000 PASS；云端仍使用 fake HTTP |
| 目标与部署能力 | 原生 PL 检查计数、容差带、窗口与边沿；真实入口在构建前拒绝不支持目标 | 配置必要条件；实际信号与预算仍可能超时 |
| 早期失败归档 | 模型请求前分配 ID，目标／服务错误与审批也入历史，执行沿用同一 ID | task_entry 只读；归档失败保留已有工具证据并报错 |
| 模型来源统一 | UI／CLI／Orchestrator 使用公共 allowlist 元数据 | 请求配置，不认证第三方权重；不记录 Key 或授权头 |
| 产品视图 | 目标、阶段、轮次、分析摘要、diff、Before/After、终态 | JSON 折叠；数值来自结构化证据 |
| structured event | events.py；Controller/Orchestrator/UI/report 共用，新增隔离订阅 | LED 直接消费事件；不搜索日志猜阶段 |
| UI 安全 | textContent、原始 payload、bidi 可见、CSRF/Origin/Host | Key 不进入状态；审批只发当前 ID/指纹 |
| v4 配置 | 示例与新部署向导采用 v4 SHA 和独立 UART | 不覆盖用户本地配置；不自动写启动镜像 |
| prog_done 状态更新 | 当前部署路径标记已实测 | 不声称运行镜像身份认证 |
| one-click / packaging | start_ui.bat、start_demo.bat、源码启动脚本、可选 console entry | 无需 PYTHONPATH；运行依赖为标准库 |
| 原始实测记录 | validation/first-real-loop-2026-10-28.md | 明确原实测跳过 UART；不夸大为新版四接口验收 |
| Windows 回归 | 用户最新 LED 28 项、1.943 s、OK 截图，438 项全量通过反馈；AI 四场景正确 | 本次新增 17 项 UART 待 Windows；当前 Linux 457 项通过 |
| 智调名称与 UI 修复 | 统一中文名／ZHITIAO；阶段按当前轮次，UART 失败显示，快照一致 | 不修改既有包名、配置路径或硬件接口 |
| 冷启动可靠性 | 记录公钥 reboot 丢失，PL 自恢复仍 P2 | 未实现启动文件修改或自动恢复 |
| GPIO 自动初始化 | 后续 v0.6 范围 | 未扩大到任意引脚／外设 |
| 可选 LED | status_indicator；固定四位 bank、四工具进度／错误双闪、配置绑定与独立 worker | 28 项专项，含线程启动失败隔离；默认关闭，地址／bitstream 待真机 |
| 更多协议 / 外壳 | 后续扩展 | 不阻塞本版 UART/UI 主线 |

PC 端标准库启动窗口负责可信文件选择，网页保持固定部署范围。当前提供本地浏览器控制台，不引入额外 GUI 框架或打包器；后续可以增加 WebView／安装包。
