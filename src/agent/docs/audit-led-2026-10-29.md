## 本次发现并修复的边界

通过故障注入复现：LED 的 Thread.start 抛 RuntimeError 后，事件总线虽隔离了该错误，适配器仍保存未启动的 Thread；随后工具 success=true，CLI 返回时 close 会尝试 join 它，导致清理报错。这会破坏“显示故障不影响主流程”的边界。

修复：创建／启动失败时立即清除线程引用、停用本次适配器，只发一次固定 warning 和结构化错误；后续工具照常执行，清理不 join 无效对象。新增 2 项回归：一项检查无重试和清理，一项检查完整 CLI 四工具 FAIL→AI diff→PASS 在此故障下仍成功。

本轮 LED 专项 28 项及全量 440 项在 Linux Python 3.13 通过，均为离线 fake transport／writer。未重跑已通过的线上 AI 场景，没有真实模型费用或板端写入。

## 尚需验收或继续保留的限制

1. 新增 LED bitstream、0x43C60000 可访问性、输出方向和 active-low 实灯效果，仍待板卡独立验收。旧 v4 SHA 或 prog_done=1 不能替代新 GPIO 的证明。
2. 普通闪烁／双闪为 PC worker 经 SSH 驱动，频率受 transport 延迟影响；要在真实网络下观察。短工具阶段可能直接显示完成态。
3. 四接口真机整链和 UI 展示仍需新证据：不能把既有 PL-only 真机闭环或模拟 UART 当作正式四工具完成。
4. LED 双闪由活动进程维持；退出后保留最后写入值，不承诺持续双闪。较晚的 warning 可能晚于某份 JSON 快照，终端和实时事件仍保留警告。
5. SSH 公钥持久化、PL 冷启动恢复仍按用户约定列 P2；GPIO 自动初始化、更多协议和安装包属于后续扩展。SD 日志归档／清理尚未实现，当前审计报告保存在 PC。

本轮对照范围内未发现其他主线规则的新增软件缺项。以上板卡验收与明确延期部分继续保留为待办，不因为单元测试全绿而标记完成。
