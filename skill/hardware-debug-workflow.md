# 可信 AI 调试闭环

## 适用范围
适用于有可重建固件、可编程目标板和独立物理反馈的系统；当前实例为PC→Zynq→STM32。

## 使用步骤
1. 把自然语言转换为可测量目标，核对完整周期与翻转间隔。
2. 批准工程、文件白名单、目标、预算和最多轮次。
3. 构建→验证产物→烧录→UART→独立物理测量。
4. 失败时向模型提供真实证据；仅生成单文件diff，人工确认后应用。
5. 重新完整验证，直到PASS、预算耗尽或停止。

## 验证方法与已验证效果
data/final_run_sanitized.json两轮真实四工具：601.7169→1001.08682 ms；提案、审批及SHA可追溯。
复用前运行Agent对应离线测试，并在自己的板卡上重做同类测试；当前实例不替代新平台验收。

## 来源
从模型不能自证PASS、目标／产物／源码需要绑定的集成经验提炼。

## 失效条件
没有独立证据、项目不在白名单、源码被外部改动、模型要求任意命令、预算不足时停止；未知硬件不套用寄存器。

## 可执行的软件检查

从仓库根目录先执行 `python sim/check_release.py` 核对参考证据；再进入 `src/agent`，设置 `PYTHONPATH=src` 后运行：

```text
python -B -m unittest discover -s tests -p "test_v05_workflow.py" -v
```

Windows使用Python3.13时可将python换为`py -3.13`。这些是离线验证，硬件迁移还须按report/reproduction.md重新部署并获得自己的实测报告。
